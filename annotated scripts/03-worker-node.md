## step 1

`set -e`

**What?**

this makes the script terminate immediately if it runs into any errors.

**Why?**

this is a good thing to turn on because if the script runs into some errors and it still continues the VM can be corrupted or installation can be incomplete resulting in a useless VM and wasted time.

## step 2

```bash

if [ "$EUID" -ne 0 ]; then
    echo "Please run as root or with sudo"
    exit 1
fi

```

**What?**
This Checks whether we have root permissions or not before executing the rest of the script.

**Why?**
if we don't have proper root permissions doing kernel level changes is not possible. to ensure smooth installation this is mandatory.

**The Concept of ROOT PERMISSSIONS:** root permissions means the highest number of permissions one can have to make changes in a Virtual machine. with root permissions we can do whatever changes we feel like.

## step 3

```bash
JOIN_CMD="$*"

if [ -z "$JOIN_CMD" ]; then
    echo "Enter the full 'kubeadm join' command from your control plane output:"
    read -r JOIN_CMD
fi

if [ -z "$JOIN_CMD" ]; then
    echo "Error: No join command provided. Exiting."
    exit 1
fi

echo "Joining cluster..."
eval "$JOIN_CMD"
```

**What?**

the first command stores everything passed to the script as a single variable named JOIN_CMD.

the first if statement checks whether we passed the join command while running the script. if not, it asks us to manually paste the full kubeadm join command.

the second if statement checks again to make sure we actually entered something. if the command is still empty, the script exits instead of continuing.

the last command executes the kubeadm join command which connects this worker node to the kubernetes control plane.

**Why?**

every worker node needs a unique join command generated by the control plane. this command contains the API server address, a bootstrap token and a certificate hash used to securely join the cluster.

by checking whether the command exists before running it, the script avoids trying to execute an empty command which would immediately fail.

**The Concepts**

**kubeadm join:** this command is generated by the control plane after running kubeadm init. it allows another machine to securely join the kubernetes cluster as a worker node.

**Bootstrap Token:** a temporary authentication token generated by the control plane. worker nodes use it to prove they are allowed to join the cluster.

**Certificate Hash:** this is the SHA256 hash of the control plane's public certificate. before joining, the worker node verifies this hash to make sure it is talking to the correct control plane and not an attacker pretending to be one.

**eval:** eval tells the shell to execute the contents of a variable as if it had been typed directly into the terminal. in this case, it executes the full kubeadm join command stored inside JOIN_CMD.
