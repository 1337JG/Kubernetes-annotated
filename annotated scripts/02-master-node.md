## step 1

`set -e`

**What?**

this makes the script terminate immediately if it runs into any errors.

**Why?**

this is a good thing to turn on because if the script runs into some errors and it still continues the VM can be corrupted or installation can be incomplete resulting in a useless VM and wasted time.

## step 2

```bash

if [ "$EUID" -ne 0 ]; then
    echo "Please run as root or with sudo"
    exit 1
fi

```

**What?**
This Checks whether we have root permissions or not before executing the rest of the script.

**Why?**
if we don't have proper root permissions doing kernel level changes is not possible. to ensure smooth installation this is mandatory.

**The Concept of ROOT PERMISSSIONS:** root permissions means the highest number of permissions one can have to make changes in a Virtual machine. with root permissions we can do whatever changes we feel like.

## step 4

```bash
echo "[2/4] Setting up non-root kubeconfig environment..."
TARGET_USER=${SUDO_USER:-$(whoami)}
TARGET_HOME=$(eval echo ~$TARGET_USER)
```

**What?** these commands setup the environment for kubeconfig. simply it allows to run kubectl commands without typing sudo everytime.

**Why?** for ease of access and this is advised for safety reasons. one reason being to avoid sudo spam every command.

---

## step 5

```bash
mkdir -p "$TARGET_HOME/.kube"
cp -i /etc/kubernetes/admin.conf "$TARGET_HOME/.kube/config"
chown -R "$TARGET_USER:$TARGET_USER" "$TARGET_HOME/.kube"
```

**What?**

first command creates a hidden directory named `.kube` inside the user's home directory.

second command copies kubernetes's admin configuration file into that directory.

third command changes the ownership of the folder so the normal user can access it.

**Why?**

after `kubeadm init`, kubernetes creates an admin configuration file which contains all the information required to connect to the API server.

if we don't copy this file, `kubectl` doesn't know where the cluster is or how to authenticate with it.

changing the ownership is also important because the file was created by root. if ownership isn't changed, the normal user won't have permission to use it.

**The Concepts**

**kubeconfig:** kubeconfig is a configuration file used by `kubectl` to know which cluster to connect to, which user credentials to use and where the kubernetes API server is located.

**admin.conf:** this is the administrator kubeconfig file generated by `kubeadm init`. it contains cluster certificates and admin credentials which allow full control over the cluster.

## step 6

```bash
echo "[3/4] Deploying Calico Container Network Interface (CNI)..."
SU_EXEC="sudo -u $TARGET_USER"
$SU_EXEC kubectl apply -f https://raw.githubusercontent.com/projectcalico/calico/v3.28.0/manifests/calico.yaml
```

**What?**

these commands download and install the calico CNI (container network interface) into the kubernetes cluster.

**Why?**

by default kubernetes does not provide networking between pods.

without installing a CNI plugin, pods can be created but they won't be able to communicate with each other across different nodes.

calico creates the networking required for pods to talk to each other and also provides features like network policies.

**The Concepts**

**CNI (Container Network Interface):** CNI is a standard used by kubernetes to connect containers and pods to a network. kubernetes itself doesn't implement networking, instead it asks a CNI plugin like calico, flannel or cilium to do it.

**Calico:** calico is one of the most popular CNI plugins. it provides pod networking, routing and network security policies for kubernetes clusters.

**kubectl apply:** this command sends a YAML manifest to the kubernetes API server. kubernetes then creates all the resources described inside the YAML file.

## step 7

```bash
echo "[4/4] Installing Helm package manager..."
curl -fsSL -o get_helm.sh https://raw.githubusercontent.com/helm/helm/main/scripts/get-helm-3
chmod 700 get_helm.sh
./get_helm.sh
rm get_helm.sh
```

**What?**

first command downloads the official helm installation script.

second command gives execute permissions to the script.

third command runs the installation.

last command removes the installation script since it is no longer needed.

**Why?**

helm is the most popular package manager for kubernetes.

instead of manually writing and applying dozens of YAML files, helm allows us to install complex applications using a single command.

many popular kubernetes applications like prometheus, ingress-nginx, cert-manager and headlamp are commonly installed using helm.

**The Concepts**

**Helm:** helm is the official package manager for kubernetes. instead of downloading and applying many YAML files manually, helm packages them together into something called a chart.

**Chart:** a chart is a collection of kubernetes YAML manifests bundled together. installing a chart creates all the resources needed to deploy an application.

**Package Manager:** a package manager is software used to download, install and manage applications. for example, `apt` installs software for ubuntu, while helm installs applications for kubernetes.
